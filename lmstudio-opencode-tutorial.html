先搞懂原理：這套組合是怎麼運作的？

動手之前，先用 30 秒理解三個角色各自負責什麼，之後遇到問題才知道「要回哪一邊處理」。

角色一

LM Studio —— 「模型倉庫＋伺服器」。負責下載 .gguf 格式的本地模型、把模型載入你的 GPU／記憶體，並在 127.0.0.1:1234 開一個與 OpenAI 格式相容的 API 伺服器。

角色二

OpenCode —— 「終端機 AI 編程助手」。本身不附帶模型，它透過 HTTP 呼叫 LM Studio 的 API，把你的程式碼上下文送給本地模型，再接收回覆。

角色三

Gemma 4 26B —— Google 推出的第一主力模型（26B 參數），中文與程式能力均衡，本教學中的第一模型。

角色四

Qwen 3 —— Alibaba 的第二模型，速度快、省資源，適合日常對話與輔助修改，本教學中的第二模型。

一句話總結

LM Studio 管模型，OpenCode 管工作流程；唯一需要你動手接的地方，就是第 06 章那份不到 20 行的設定檔。

02

安裝 LM Studio（模型倉庫 + 伺服器）

LM Studio 是一個桌面應用程式，負責「下載模型 → 載入模型 → 提供 API」。整份教學只有下載階段需要網路。

1

前往官方網站下載安裝檔

打開瀏覽器至 lmstudio.ai（官方網址：https://lmstudio.ai），首頁會依你的作業系統自動推薦版本：

  • Windows：下載 .exe 安裝程式（支援 x64 與 ARM）
  • macOS：下載 .dmg（Apple Silicon 與 Intel 都有對應版本）
  • Linux：提供 AppImage（執行前記得 chmod +x）
2

執行安裝程式

雙擊下載的檔案，一路按「下一步」即可，沒有捆綁軟體。第一次啟動可能跳出防火牆詢問（Windows），允許存取即可——這是為了讓它綁定本機的 127.0.0.1 埠。

3

認識主介面（只需要記住兩個分頁）

安置完成後你會看到主視窗。目前只需要關心頂部這幾個分頁：Chat（跟模型聊天測試用）、Developer（開關伺服器用，第 04 章會回到這裡）。

03

下載模型：Gemma 4 26B 與 Qwen 3

模型是「權重檔」（外觀為 .gguf 格式），放在硬碟裡由 LM Studio 管理。這一章會下載兩個模型，下載量較大，請連接穩定的網路。

◆3-1　第一模型：Gemma 4 26B（主力）

1

開啟模型搜尋

在 LM Studio 左側點 Models（放大鏡／商店圖示，依版本可能叫「搜尋模型」），在搜尋框輸入 gemma 4 26b。

2

挑選量化版本（Quantization）

搜尋結果會列出很多檔案。量化程度決定檔案大小與品質，新手請看下表選：

量化版本檔案大小（約）需要 RAM/VRAM品質適合
Q4_K_M~16 GB18 GB良好 ★★★★✅ 本教學推薦 — 甜點級
Q5_K_M~18.5 GB21 GB更好 ★★★★☆RAM 32GB 以上再考慮
Q8_0~28 GB31 GB接近原版 ★★★★★進階玩家／高階硬體
原版 BF16~53 GB56 GB100%不建議（太吃資源）
3

點下 Download

選擇 Gemma 4 26B Instruct · Q4_K_M（挑選 GGUF 格式），按 Download。視窗右下角會顯示進度，約 16 GB，喝杯咖啡等等。

◆3-2　第二模型：Qwen 3（快取落二號位）

1

搜尋 qwen3，依硬體挑尺寸

同一個搜尋介面，輸入 qwen3。Qwen 3 系列尺寸很多，挑選原則：

你的情況推薦下載檔案大小定位
RAM 16 GB、剛剛 Gemma 跑得很吃力Qwen3-8B-Q4_K_M~5 GB輕快二號位
RAM 32 GB、Gemma 還有餘裕 ⭐ 推薦Qwen3-14B-Q4_K_M~9 GB品質與速度平衡
RAM 64 GB／VRAM 24 GBQwen3-30B-A3B-Q4_K_M~18 GBMoE 架構，品質接近旗艦、速度反直覺地快
2

同樣選 Instruct 版本下載

如同 Gemma，盡量挑選名稱裡帶 Instruct（對話指令微調版）的檔案，它最適合被 OpenCode 這類「工具」呼叫。

💡 什麼是量化？30 秒加分知識

模型原始權重每個數字用 16 bit 儲存（BF16）。量化的意思是：以些微精度換取大幅體積縮減——Q4 就是每個數字只存 4 bit。對日常使用而言，Q4_K_M 的品質損失通常難以察覺，但檔案縮小到原本的 1/3，這也是「16 GB 就能跑 26B 模型」的原因。

⚠ 低配替代方案（RAM 只有 16 GB 看這裡）

Gemma 26B 對 16 GB 機器太勉強。替代路線：第一模型改下 Gemma 4 12B Q4（約 7.5 GB），第二模型下 Qwen3-8B Q4（約 5 GB）。設定檔只需改名稱（第 06 章會提醒），其餘步驟完全相同。

3

下載完成後，先在 Chat 分頁各測一句話

點 Chat → 在上方模型選單挑 Gemma → 打一句 你好，自我介紹一下。能順利回覆就代表模型健康。換 Qwen 3 再測一次。這步可提早抓出損壞的下載檔。

04

啟動本機 API 伺服器

這一步是整套串接的樞紐：把 LM Studio 變成一台「跑在你電腦裡的 OpenAI 相容伺服器」，網址固定為 http://127.0.0.1:1234。

1

切到 Developer 分頁，把伺服器打開

點頂部 Developer 分頁 → 找到畫面中央的 Status: Stopped → 點 Start Server。成功後亮起綠燈，狀態變成 Running on port 1234。

2

確認 Just-in-Time Model Loading 是開的

在 Developer 分頁找這個開關，打開它。效果：OpenCode 送請求時指定某個模型，LM Studio 會自動把它載入記憶體（必要時先卸載別的模型）。這樣你就能在 OpenCode 裡自由切換 Gemma ↔ Qwen，不用手動點 LM Studio。

3

驗證伺服器真的活著（三種方法任選）

方法 A：Windows PowerShell / 終端機 直接 curl
PS> curl http://127.0.0.1:1234/v1/models

期望看到類似這樣的 JSON（注意 id 欄位的值，第 06 章設定檔要照抄它們）：

回傳（示意）
{
  "data": [
    { "id": "gemma-4-26b-instruct",   "object": "model" },
    { "id": "qwen3-14b-instruct",     "object": "model" }
  ]
}
方法 B：瀏覽器直接開網址
在瀏覽器網址列貼上 → http://127.0.0.1:1234/v1/models
能看到上面的 JSON 即成功。
方法 C：直接發一則對話測試（選做）
curl http://127.0.0.1:1234/v1/chat/completions -H "Content-Type: application/json" -d "{\"model\":\"gemma-4-26b-instruct\",\"messages\":[{\"role\":\"user\",\"content\":\"用一句話介紹你自己\"}]}"
💡 小心引號

PowerShell 對 " 的逸出比較嚴格（如上示用 \"）。若 curl 語法一直報錯，直接跳過方法 C 用方法 A/B 驗證就好——反正 OpenCode 連上後自然會實測。

05

安裝 OpenCode（終端機 AI 編程助手）

OpenCode 是一個跑在終端機裡的 AI 編程代理。它可以讀整個專案、直接編輯檔案、執行指令——而現在，這些事的「腦」換成你自己的本地模型。

1

先確認 Node.js（18 以上）

檢查指令（不分平台）
PS> node --version
v22.11.0   ← 有輸出任何 v18+ 的版本號就 OK

沒有 Node.js 的話，到 nodejs.org 下載 LTS 版安裝（一路下一步）。

2

安裝 OpenCode — 依平台選擇

Windows（推薦 npm）
PowerShell
PS> npm i -g opencode-ai
macOS / Linux
Terminal
$ curl -fsSL https://opencode.ai/install | bash
# 或：npm i -g opencode-ai / brew install opencode
3

驗證安裝成功

檢查版本
PS> opencode --version
1.2.3   ← 有出現版本號就成功了
⚠ 問都不用問，跳過登入

看到的教學常教 opencode auth login 貼 API 金鑰——那是給雲端模型用的。本地模型完全不需要任何金鑰，直接跳到第 06 章設定檔即可。

06

設定串接：讓 OpenCode 看見你的本地模型

整份教學的核心一步，只有一份 JSON 設定檔。告訴 OpenCode：「有個供應商叫 LM Studio，網址是本機，手下有 Gemma 和 Qwen 兩個模型。」

◆6-1　決定設定檔放哪裡

放的位置路徑作用範圍建議
全域設定~/.config/opencode/opencode.json
Windows: %USERPROFILE%\.config\opencode\opencode.json		所有專案都能用✅ 推薦新手用這個
專案設定你的專案/opencode.json僅該專案適合不同專案用不同模型
1

建立設定檔

在上述目錄用任何編輯器建立 opencode.json，貼入下方內容（Windows 可用 PowerShell 快速建立資料夾）。

opencode.json — 完整內容（可直接複製）
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "lmstudio": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "LM Studio（本機）",
      "options": {
        "baseURL": "http://127.0.0.1:1234/v1"
      },
      "models": {
        "gemma-4-26b-instruct": { "name": "Gemma 4 26B — 主力" },
        "qwen3-14b-instruct":   { "name": "Qwen 3 14B — 快取二號" }
      }
    }
  }
}
🛑 最容易出錯的兩個地方

1. 模型 ID 必須與 LM Studio 的一致。回看第 04 章方法 A，教學 placeholder 是 gemma-4-26b-instruct / qwen3-14b-instruct，但你的 LM Studio 可能叫 gemma-4-26b-it-q4_k_m 之類——以 /v1/models 回傳的 id 為準，一字不差地抄進來（key 與 name 可自訂顯示名）。

2. 沒下載 14B 就改 key。如果你第 03 章下的是 Qwen3-8B，把兩處 qwen3-14b-instruct 改成你實際的 id。（低配替代方案同理，Gemma 12B 就改成對應 id。）

2

（選做）進階參數

想在模型 key 裡加自訂推理參數也可以，例如限制上下文長度：

進階：個別模型微調（示意，可整段省略）
"gemma-4-26b-instruct": {
  "name": "Gemma 4 26B — 主力",
  "options": { "num_ctx": 32768 }   // 上下文 32K，吃得越深吃 RAM 越多
}
07

正式跑通：啟動、切換、驗收

終於到好戲登場。三個動作完成後，你就有了一套完全離線、不花一分錢的 AI 編程助手。

1

啟動順序要對

先開 LM Studio（伺服器綠燈亮著）→ 再到你的專案資料夾開 OpenCode：

到專案資料夾再啟動
PS> cd C:\projects\test-app
PS> opencode
2

選到你的模型

在 OpenCode 輸入 /models（開啟模型選單），搜尋欄打 lmstudio，應該會看到兩個模型：

  • lmstudio / gemma-4-26b-instruct → 第一模型
  • lmstudio / qwen3-14b-instruct → 第二模型

選不見代表第 06 章設定檔有誤（九成是 JSON 少個逗號，或模型 id 抄錯），去 ~/.config/opencode/ 檢查。

3

第一次對話 + 切換模型測試

依序做這四件事，全綠燈就代表跑通：

逐項測試腳本（在 OpenCode 對話框輸入）
1. 「你會用什麼程式語言？」            → Gemma 應該秒答
2. 「幫我寫一個 Python 的 hello world」 → Gemma 會產出程式碼區塊
3. 按 /models 切到 qwen3 → 再問「我剛剛說你在幹嘛？」
4. 「/init」可替專案建立說明檔（進階玩法）
⏳ 第一次切換會等一陣子

Gemma ↔ Qwen 切換時，LM Studio 需要卸載舊模型、把新模型載入記憶體，視硬體 10 秒～2 分鐘不等（Q4 量化檔很大要從硬碟讀）。只會在切換時慢一次，載入後就快了。若想避免等待：期望第 08 章的「常駐模型」技巧。

◆7-1　驗收清單

  • LM Studio 伺服器呈現綠燈 Running on port 1234
  • curl http://127.0.0.1:1234/v1/models 回傳兩個模型 id
  • opencode /models 能搜到 lmstudio 下的兩個模型
  • Gemma 能正常回覆中文與程式碼
  • 切換到 Qwen 後對話依然正常（紀錄重建，模型獨立記憶）
  • 拔掉網路線再問一句 —— 依然能回覆，恭喜你完全離線跑通 🎉
08

疑難排解：常見錯誤對症下藥

90% 的新手問題都落在下面這幾張牌。點開對照自己的症狀。

🔌OpenCode 報錯 Connection refused / Fetch failed

原因：OpenCode 根本連不上 127.0.0.1:1234。

排查順序：

  • 1. LM Studio 是否還開著？Developer 分頁狀態是 Stopped → 按 Start Server。
  • 2. 埠號是否被改過？預設 1234，若你改過要同步改 opencode.json 的 baseURL。
  • 3. 設定檔網址是否少了 /v1！（正確：http://127.0.0.1:1234/v1）
  • 4. 防火牆／防毒是否擋掉 LM Studio？允許該程式存取網路。
🚫OpenCode 回覆 404 / model not found

原因：設定檔裡的模型 id 與 LM Studio 的不符，或 LM Studio 裡根本沒有這個模型可用。

解法：重新 curl http://127.0.0.1:1234/v1/models，將回傳的 id 一字不差抄進 opencode.json。並確認下好的模型出現在 LM Studio 的 Models 分頁清單裡。

🐌回覆速度超級慢（半天吐一個字）

原因（多半）：模型完全跑在 CPU 上。

  • LM Studio → Settings → 找到 GPU Offload（每個模型可設），把層數拉高（如 999 = 全部塞 GPU）。
  • VRAM 不足以塞整顆 → 掉到更小量化（Q4）或小一號模型。
  • 關掉其他吃 RAM／VRAM 的瀏覽器分頁、遊戲後重試。

參考基準：RTX 3090 這類卡，26B Q4 可達每秒 20+ tokens；純 CPU 通常只有 2～5 tokens 之譜。

💥LM Studio 閃退 / OOM（記憶體不足）

原因：RAM／VRAM 不夠載入 26B。

  • 最直接：改下 Gemma 4 12B Q4（第 03 章替代方案），把設定檔 id 同步換掉。
  • 或下 Qwen3-8B 當第一模型先求跑通。
  • 增加 Windows 虛擬記憶體（pagefile）能撐住但不建議常態使用 — 會慢到沒心情工作。
🔀OpenCode /models 看不到 lmstudio
  • 檔名確認：是 opencode.json 不是 opencode.json.txt（Windows 常見隱藏副檔名問題）。
  • 路徑確認：~/.config/opencode/opencode.json。Windows 也是 C:\Users\你的名\.config\opencode\（不是 AppData）。
  • JSON 語法：缺逗號／引號是最常見的死因。可用線上或 VS Code 的 JSON 校驗貼上去檢查。
  • 修改後重開 OpenCode（設定不會熱載）。
🔁切換模型後，OpenCode 好像「失憶」了

這是正常設計：不同的模型上下文互不共用，切換後新模型不知道之前的對話。工作流建議：Gemma 負責主線決策與編碼，切 Qwen 做單點審查／重寫是「帶著檔案上下文去問」（OpenCode 會自動附上專案檔案，所以實務影響不大）。

🏷️兩個模型想同時常駐（進階）

RAM 64 GB 或 GPU 24 GB 以上的玩家：LM Studio → Settings 開啟 Auto Unload 關閉／多模型並行相關選項，或在 Developer 分頁手動把兩個模型都 Load，再把 JIT 關掉。之後 OpencCode 切換就是零延遲。代價是待機時記憶體壓力常駐高。

一般機器不建議 —— 切換等個一次沒關係，穩定不重要。
